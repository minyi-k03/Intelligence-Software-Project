# 모든 파이프라인이 공용 코퍼스 하나를 BM25로 검색하고, 압축도 모델 없이 BM25로

외부 API(웹 검색)는 감점 사유이고 파이프라인마다 검색 대상이 다르면 비교가 성립하지 않으므로, 평가·개발 세트 문항의 문단(HotpotQA 정답 2 + 방해 8, SQuAD 2.0 원래 문맥과 함정 문단)으로 공용 코퍼스 하나를 만들고 모든 파이프라인이 같은 BM25 도구로 검색한다. 검색 결과 압축도 학습된 모델 대신, 문단 제목을 붙인 앞뒤 1문장 창 단위의 BM25 점수로 상위 m개를 남긴다(RECOMP의 추출형 아이디어를 학습 모델 없이 적용).

## Considered Options

- **Dense retriever / 학습된 압축 모델**: 모델이 하나 더 들어가 "파이프라인별 모델 상이"로 읽힐 여지가 있고 VRAM을 더 쓴다.
- **문장 단위 압축**: 대명사로 시작하는 근거 문장과 2홉 문장이 탈락한다(2차 교차검증 지적). 제목 + 앞뒤 1문장 창으로 바꿨다.
- **웹 검색으로 근거 보충(CRAG 원안)**: 외부 API 금지. 그 자리를 기권(ABSTAIN)으로 대체했다.

## Consequences

- 함정 문단이 코퍼스에 있어야 기권이 "검색 실패"가 아니라 "근거 판단"의 결과가 된다.
- k(검색 결과 수)는 개발 세트 검색 재현율로, m(남길 문장 창 수)은 근거 문장 보존율 90% 이상인 최소값으로 데이터에서 정한다. 관행값을 쓰지 않는다.
- 검색과 압축은 모델을 부르지 않으므로 검색 경로의 모델 호출은 라우터와 "근거 판정 + 답"뿐이다.
