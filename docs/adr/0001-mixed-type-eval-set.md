# 평가 세트는 HotpotQA · SQuAD 2.0 · GSM8K를 섞은 120문항, 유형은 숨기고 같은 채점기로

교수님이 말한 "범용"은 과제 형식은 하나로 두고 내용만 다양하게 하라는 뜻이라(분류라는 하나의 과제에 강아지/고양이, 남/여처럼), 과제를 단답형 QA 하나로 고정하고 단일 홉(SQuAD 2.0), 다중 홉(HotpotQA), 수학(GSM8K)을 각 40문항씩 섞었다. 문항 유형은 에이전트에게 숨기고, 텍스트는 SQuAD 정규화 후 EM(주) + F1(보조), 수치는 숫자를 꺼내 수치로 비교한다. 단일·다중 홉 QA를 섞고 BM25와 EM+시간으로 평가한 Adaptive-RAG와 같은 구조이며, SQuAD 2.0의 답할 수 없음 문항은 기권 능력을 따로 드러낸다.

## Considered Options

- **단일 벤치마크**: 범용성을 보일 수 없고 라우터·기권의 효과가 드러나지 않는다.
- **유형을 에이전트에 알려 주기**: 유형별 프롬프트로 사실상 세 개의 에이전트가 되어 범용성 주장이 무너진다. 그래서 호출 예산도 유형별로 다르게 둘 수 없다.
- **수치 문항에도 SQuAD 정규화**: 구두점 제거로 `42.0`이 `420`이 된다(SQuAD v2 공식 채점 코드에서 직접 확인). 수치는 lm-evaluation-harness GSM8K 방식으로 따로 비교한다.

## Consequences

- 개발 세트(유형당 20문항, SQuAD는 10 + 10)를 따로 두고 튜닝·조건부 부품 채택은 여기서만 한다. 10문항이면 1문항이 10%p라 판단이 너무 거칠다.
- 평가 세트·개발 세트·공용 코퍼스는 11/12에 함께 동결하고 해시를 레포에 기록한다. 이후 변경은 "평가 세트 사후 변경" 감점이다.
- 유형당 40문항에서 McNemar p<0.05가 되려면 M만 맞힌 문항이 6개 이상(반대 0) 또는 8개 이상(반대 1)이어야 한다.
