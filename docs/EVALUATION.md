# 평가·측정 규칙

> 원본: 최종 설계안 「평가 세트·채점·공정성」, 「측정과 절제 실험」 절. 결정 이유는 [ADR-0001](adr/0001-mixed-type-eval-set.md), [ADR-0005](adr/0005-round-based-measurement.md).

## 1. 세트 구성 (11/12 동결)

| 세트 | HotpotQA | SQuAD 2.0 | GSM8K | 합계 |
|---|---|---|---|---|
| 평가 세트 | 40 (distractor dev, 다리형 20 · 비교형 20) | 40 (dev, 답 있음 20 · 답할 수 없음 20) | 40 (test) | 120 |
| 개발 세트 | 20 (다리형 10 · 비교형 10 — 제안) | 20 (답 있음 10 · 답할 수 없음 10) | 20 | 60 |

- 고정 시드로 뽑고, 시드는 `data/frozen/MANIFEST.json`에 기록한다.
- 개발 세트와 평가 세트는 문항이 겹치지 않는다.
- SQuAD 2.0은 한 문맥에 여러 질문이 달려 있으므로, 개발 세트와 평가 세트가 같은 문맥(문단)을 공유하지 않도록 문맥 단위로 나눠 뽑는다. 공유하면 개발 세트 튜닝이 평가 세트 문단에 맞춰질 수 있다. 한 문맥에서는 질문을 하나만 뽑는다(평가 40개·개발 20개 문맥이 모두 다르다). `scripts/freeze_data.py`가 이 규칙을 구현하고 검증한다.
- HotpotQA는 평가·개발 사이에 정답 문단이 겹치는지 막지 않고 MANIFEST의 `stats`에 겹친 수를 기록한다.
- 과제 형식은 단답형 QA 하나이고, 문항 유형은 에이전트에게 숨긴다.

## 2. 공용 코퍼스

- HotpotQA: 평가·개발 세트 문항마다 정답 문단 2개 + 방해 문단 8개 (distractor 설정의 10문단 그대로)
- SQuAD 2.0: 평가·개발 세트 문항의 원래 문맥. 답할 수 없음 문항의 문맥(함정 문단)도 포함
- GSM8K: 문단 없음
- 코퍼스는 두 세트의 문단으로 만들기 때문에 세트와 **함께** 동결한다. 따로 바뀌면 검색 결과가 달라진다.
- 함정 문단이 있어야 기권이 "검색 실패"가 아니라 "근거 판단"의 결과가 된다.

## 3. 채점

| 문항 | 방법 | 비고 |
|---|---|---|
| 텍스트 (HotpotQA, SQuAD 답 있음) | SQuAD 공식 정규화(소문자, 구두점·관사 제거, 공백 정리) 후 **EM(주 지표)** + F1(보조), 정답 후보 중 최대값 | |
| 답할 수 없음 (SQuAD) | 정규화 후 `UNANSWERABLE`과 일치하면 정답 | 모든 파이프라인 동일 |
| 수치 (GSM8K) | 예측에서 숫자를 꺼내(쉼표·통화 기호 제거) 정답과 **수치로** 비교 | SQuAD 정규화는 `42.0`을 `420`으로 바꾸므로 쓰지 않는다. 정답은 GSM8K 해설의 `####` 뒤 값. 숫자 추출 규칙은 lm-evaluation-harness GSM8K 설정을 참고 (TBD: A가 구현 후 여기에 명시) |
| 타임아웃 | 120초 초과 → 오답 | |

채점기는 파이프라인 종류와 무관하게 같은 함수로 모든 로그를 채점한다.

## 4. 측정 규칙

- **라운드**: 한 세션에서 한 묶음의 파이프라인을 한 번씩 실행하는 단위. 라운드마다 실행 순서를 바꾼다.
- **묶음**: 본 비교 묶음(P0 · P0-raw · P1 · M) 3라운드, 절제 묶음(M + 절제 변형) 1라운드. **서로 다른 세션**에서 돌린다.
- 시간이 남으면 기여가 큰 부품의 절제 변형부터 라운드를 늘린다.
- 문항마다 `.jsonl`에 즉시 저장, 세션이 끊기면 이어서 돈다.
- 시간 = 문항 입력 ~ 최종 답. 모델 로딩과 첫 1문항(워밍업) 제외.
- VRAM = `nvidia-smi` 0.5초 간격 최대치. 최대 컨텍스트 = 호출별 입력 토큰 수의 최대값.
- 라운드마다 GPU 정보를 기록하고, 측정 중 Ollama 모델 유지 시간(`keep_alive`)을 고정한다.
- 채점자 재실행용으로 소수 문항만 도는 **검증 모드**를 노트북에 둔다.
- 측정 시작 전에 동결 데이터 해시를 확인한다.

## 5. 지표

| 구분 | 지표 |
|---|---|
| 주 지표 | 정확도 (전체 120 · 유형별 40) |
| 보조 정확도 | F1 (텍스트 문항), 답할 수 없음 정답률 |
| 비용 | 문항당 호출 수(예산 포함분 / 재시도 포함 총합), 입력·출력 토큰, 시간(평균·중앙값), 최대 VRAM, 최대 컨텍스트 |
| 부작용 | 과잉 기권률, 예산 소진 수, 잘림 수, 파싱 실패 수, 루프 끊기 발동 수, 근거 문장 보존율 |

- 절제 변형의 시간·호출 수는 같은 묶음 안 M 대비 **비율**로 보고하고, 보고서에 "절제 변형은 1라운드 측정"이라고 명시한다.
- temperature 0이라 정확도는 라운드마다 거의 같다. TBD(D): 라운드 간 정확도가 다를 때의 대표값 규칙.

## 6. 통계

- McNemar 정확 검정: 유형별 40문항, 전체 120문항 교차표 각각.
- 유형당 40문항에서 p<0.05가 되려면 M만 맞힌 문항이 6개 이상(반대 0개) 또는 8개 이상(반대 1개).
- GSM8K는 "정확도 유지 + 효율 개선"이 목표.

## 7. 공정성 체크

- [ ] 모든 파이프라인이 같은 답 형식 지시문 (P0 최소화, P0-raw 없음)
- [ ] P1과 M이 같은 도구 구현·같은 오류 처리
- [ ] 같은 모델 태그, temperature 0, num_ctx 8192
- [ ] 모든 파이프라인이 UNANSWERABLE로 기권 가능 (P0는 [INTERFACES §6](INTERFACES.md) 결정에 따름)
- [ ] 튜닝은 개발 세트에서만
