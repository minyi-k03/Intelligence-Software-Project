# 평가·측정 규칙

> 원본: 최종 설계안 「평가 세트·채점·공정성」, 「측정과 절제 실험」 절. 결정 이유는 [ADR-0001](adr/0001-mixed-type-eval-set.md), [ADR-0005](adr/0005-round-based-measurement.md).

## 1. 세트 구성 (11/12 동결)

| 세트 | HotpotQA | SQuAD 2.0 | GSM8K | 합계 |
|---|---|---|---|---|
| 평가 세트 | 40 (distractor dev, 다리형 20 · 비교형 20) | 40 (dev, 답 있음 20 · 답할 수 없음 20) | 40 (test) | 120 |
| 개발 세트 | 20 (다리형 10 · 비교형 10 — 제안) | 20 (답 있음 10 · 답할 수 없음 10) | 20 | 60 |

- 고정 시드로 뽑고, 시드는 `data/frozen/MANIFEST.json`에 기록한다.
- 개발 세트와 평가 세트는 문항이 겹치지 않는다.
- SQuAD 2.0은 한 문맥에 여러 질문이 달려 있으므로, 개발 세트와 평가 세트가 같은 문맥(문단)을 공유하지 않도록 문맥 단위로 나눠 뽑는다. 공유하면 개발 세트 튜닝이 평가 세트 문단에 맞춰질 수 있다. 한 문맥에서는 질문을 하나만 뽑는다(평가 40개·개발 20개 문맥이 모두 다르다). `scripts/freeze_data.py`가 이 규칙을 구현하고 검증한다.
- HotpotQA는 평가·개발 사이에 정답 문단이 겹치는지 막지 않고 MANIFEST의 `stats`에 겹친 수를 기록한다.
- 과제 형식은 단답형 QA 하나이고, 문항 유형은 에이전트에게 숨긴다.

## 2. 공용 코퍼스

- HotpotQA: 평가·개발 세트 문항마다 정답 문단 2개 + 방해 문단 8개 (distractor 설정의 10문단 그대로)
- SQuAD 2.0: 평가·개발 세트 문항의 원래 문맥. 답할 수 없음 문항의 문맥(함정 문단)도 포함
- GSM8K: 문단 없음
- 코퍼스는 두 세트의 문단으로 만들기 때문에 세트와 **함께** 동결한다. 따로 바뀌면 검색 결과가 달라진다.
- 함정 문단이 있어야 기권이 "검색 실패"가 아니라 "근거 판단"의 결과가 된다.

## 3. 채점

| 문항 | 방법 | 비고 |
|---|---|---|
| 텍스트 (HotpotQA, SQuAD 답 있음) | 추출한 답(§3.1)을 SQuAD 공식 정규화(소문자, 구두점·관사 제거, 공백 정리) 후 **EM(주 지표)** + F1(보조), 정답 후보 중 최대값 | 예측이 비었거나 `UNANSWERABLE`이면 EM·F1 모두 0 |
| 답할 수 없음 (SQuAD) | 추출한 답이 정규화 후 `unanswerable`과 **정확히 일치**할 때만 정답 | `UNANSWERABLE because ...`는 오답. EM·F1은 같은 값(정답 1, 오답 0)으로 기록한다(SQuAD v2 방식). 모든 파이프라인 동일 |
| 수치 (GSM8K) | 추출한 답(§3.1)에서 **마지막 숫자**를 꺼내(§3.2) 정답과 **수치로** 비교 | SQuAD 정규화는 `42.0`을 `420`으로 바꾸므로 쓰지 않는다. 정답은 GSM8K 해설의 `####` 뒤 값(동결 데이터 60개 모두 정수 문자열). lm-evaluation-harness GSM8K의 flexible-extract와 같은 방식 |
| 타임아웃 | 120초 초과 → 오답 | |

채점기(`src/eval/scorer.py`)는 파이프라인 종류와 무관하게 같은 함수로 모든 로그를 채점한다. 결정 배경: TBD #4(P0에도 기권 문구)·#5(`Final answer:` 접두어, 숫자 추출 규칙), 팀 3인 동의.

### 3.1 최종 답 추출 (모든 파이프라인 공통)

`extract_final_answer(raw)`:

1. 출력에 `Final answer:`(대소문자 무시)가 있으면 **마지막** 것 뒤의 **첫 번째 비어 있지 않은 줄**, 없으면 출력 **전체**를 쓴다.
2. `**Final answer:** 42`, `**Final answer**: 42`, `Final answer:` 다음 줄에 답이 오는 경우도 같은 규칙으로 처리한다. 정리하면 빈 줄이 되는 줄(`***` 구분선 등)은 건너뛴다.
3. 양끝 공백·따옴표·`**`·문장 끝 마침표를 제거한다.
4. 접두어 뒤가 비어 있으면 빈 답이다.

P0-raw처럼 접두어 없이 답하는 경우 출력 전체가 답이 되므로 EM이 낮게 나온다. 참고용이며 결과표에 그대로 표시한다.

### 3.2 숫자 추출과 비교 (GSM8K)

`extract_number(text)`는 추출한 답에서 **마지막 숫자**를 수치로 꺼낸다(접두어가 없으면 출력 전체의 마지막 숫자).

| 규칙 | 예 |
|---|---|
| 쉼표(천 단위)·통화 기호(`$ € £`)·`%`·단위 단어는 무시하고 값은 바꾸지 않는다 | `$1,234` → 1234, `50%` → 50 |
| 천 단위가 아닌 쉼표는 지우지 않는다 | `5, 6` → 마지막 숫자 6 |
| 유니코드 마이너스(`−`)를 `-`로 읽고, 소수·음수를 허용한다 | `−5` → -5, `42.0` = `42`, `.5` = 0.5 |
| 숫자 사이 하이픈은 음수 부호가 아니다 | `3-5`, `10-5` → 5 |
| 분수 `a/b`는 나눈 값으로 비교한다. 분모가 0이면 숫자 없음 | `3/4` → 0.75 |
| 영어 숫자 단어는 변환하지 않는다 (오답) | `eight` → 숫자 없음 |
| 숫자가 없으면 오답 | `UNANSWERABLE` |

- 답 부분에 숫자가 여러 개면(`Final answer: 18 (9 x 2)`) 마지막 숫자(2)가 뽑혀 오답이 된다. 규칙은 바꾸지 않고, 공통 지시문의 "숫자 답이면 숫자만"([INTERFACES §6](INTERFACES.md))으로 줄인다. 이런 출력의 수는 로그의 `answer`에 `count_numbers`를 적용해 센다.

### 3.3 기권·빈 답

- 기권은 추출한 답이 정규화 후 `UNANSWERABLE`과 정확히 같을 때다(`is_abstained`). P0·P1·M 모두 같은 함수로 `PipelineResult.abstained`를 정하고, 과잉 기권률 집계도 이 기준을 쓴다.
- 빈 답은 어느 파이프라인에서도 기권으로 바꾸지 않고 오답으로 둔다. 텍스트 문항에서 SQuAD 공식의 "빈 토큰끼리 F1 1.0" 규칙은 쓰지 않는다.

## 4. 측정 규칙

- **라운드**: 한 세션에서 한 묶음의 파이프라인을 한 번씩 실행하는 단위. 라운드마다 실행 순서를 바꾼다.
- **묶음**: 본 비교 묶음(P0 · P0-raw · P1 · M) 3라운드, 절제 묶음(M + 절제 변형) 1라운드. **서로 다른 세션**에서 돌린다.
- 시간이 남으면 기여가 큰 부품의 절제 변형부터 라운드를 늘린다.
- 문항마다 `.jsonl`에 즉시 저장, 세션이 끊기면 이어서 돈다.
- 시간 = 문항 입력 ~ 최종 답. 모델 로딩과 파이프라인마다 첫 1문항(워밍업)은 시간·비용 집계에서 제외한다. 정확도·McNemar는 워밍업 문항을 포함한 전체 문항으로 낸다 ([INTERFACES §7.2](INTERFACES.md)).
- 120초를 넘긴 문항은 오답이다. 러너가 그 작업을 중단시키지만 호출 기록은 수거하지 못하므로, 시간 초과 문항의 호출 수·토큰은 실제보다 적게 기록된다(시간은 제한 시간으로 기록). 비용 집계에서 시간 초과 수를 함께 보고한다.
- VRAM = `nvidia-smi` 0.5초 간격 최대치. 최대 컨텍스트 = 호출별 입력 토큰 수의 최대값.
- 라운드마다 GPU 정보를 기록하고, 측정 중 Ollama 모델 유지 시간(`keep_alive`)을 고정한다.
- 채점자 재실행용으로 소수 문항만 도는 **검증 모드**를 노트북에 둔다.
- 측정 시작 전에 동결 데이터 해시를 확인한다.

## 5. 지표

| 구분 | 지표 |
|---|---|
| 주 지표 | 정확도 (전체 120 · 유형별 40) |
| 보조 정확도 | F1 (텍스트 문항 = `answer_kind=text`만. 답할 수 없음 문항의 F1은 EM과 같은 값이라 섞지 않는다), 답할 수 없음 정답률 |
| 비용 | 문항당 호출 수(예산 포함분 / 재시도 포함 총합), 입력·출력 토큰, 시간(평균·중앙값), 최대 VRAM, 최대 컨텍스트 |
| 부작용 | 과잉 기권률, 예산 소진 수, 잘림 수, 파싱 실패 수, 루프 끊기 발동 수, 근거 문장 보존율 |

- 절제 변형의 시간·호출 수는 같은 묶음 안 M 대비 **비율**로 보고하고, 보고서에 "절제 변형은 1라운드 측정"이라고 명시한다.
- 본 비교 정확도는 문항별 3라운드 정오답의 다수결을 사용한다. 보조 F1은 워밍업을 포함한 세 라운드의 텍스트 문항 실행에서 평균을 낸다. 문항별 시간·호출 수·토큰 지표는 각 라운드의 워밍업을 제외한다.
- 과잉 기권률은 답할 수 있는 문항 실행 중 기권한 비율이다. 근거 문장 보존율은 보존 여부가 기록된 HotpotQA 문항 실행을 분모로 삼는다. 예산 소진은 문항 실행 건수, 잘림과 파싱 실패는 호출 건수, 루프 끊기는 발동 횟수를 합산한다. 파싱 성공 여부를 기록한 호출이 없으면 미측정으로 표시한다.

## 6. 통계

- M과 P1의 문항별 다수결 정오답을 문항 ID로 대응시켜 양측 McNemar 정확 검정을 계산한다. 유형별 40문항과 전체 120문항의 교차표를 각각 보고한다.
- 유형당 40문항에서 p<0.05가 되려면 M만 맞힌 문항이 6개 이상(반대 0개) 또는 8개 이상(반대 1개).
- GSM8K는 "정확도 유지 + 효율 개선"이 목표.

## 7. 공정성 체크

- [ ] 모든 파이프라인이 같은 답 형식 지시문: 내용 문장은 P0·P1·M이 같은 상수, `Final answer:` 형식 줄은 자유 서술 호출(P0·P1·M 수학 경로)에만 ([INTERFACES §6](INTERFACES.md)). P0-raw는 지시문 없음
- [ ] P1과 M이 같은 도구 구현·같은 오류 처리
- [ ] 같은 모델 태그, temperature 0, num_ctx 8192
- [ ] 모든 파이프라인이 UNANSWERABLE로 기권 가능. P0도 최소 지시문에 기권 문구를 포함한다(TBD #4 결정). 예외는 질문만 주는 P0-raw로, 기권 불가이며 결과표에 그대로 표시한다
- [ ] 튜닝은 개발 세트에서만
