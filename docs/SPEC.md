# 구현 명세 — M(EBA)

> 원본: 「3조 지능형 소프트웨어 기말 프로젝트 최종 설계안」(2026-11-08, 승인됨)
> 이 문서는 구현에 필요한 내용만 추린 것입니다. 원본과 다르면 원본을 따르고, 이 문서를 고칩니다.

## 1. 목표

고정 모델(Qwen2.5-7B-Instruct 4-bit)은 그대로 두고 하네스만 바꿔, P1(표준 ReAct)보다 **정확도는 높고 호출 수·시간은 P1 이하**인 단일 에이전트 M(EBA)을 만든다.

결과 보고 형식: `P1 대비 정확도 +Δ, 호출 수 ×k, 추론 시간 ×t, 최대 VRAM n GB`

## 2. 고정 조건

| 항목 | 값 |
|---|---|
| 모델 | Qwen2.5-7B-Instruct 4-bit (모든 파이프라인 동일) |
| 서빙 | Ollama · temperature 0 · num_ctx 8192 |
| 호출 | 모든 호출을 LangChain `ChatOllama`로. 모델 태그는 설정 한 곳에서만 정의 |
| 도구 | BM25 검색, 계산기 (P1과 M이 같은 도구를 쓴다) |
| 과제 | 단답형 QA 하나. 문항 유형은 에이전트에게 숨긴다 |
| 프롬프트 언어 | 영어 |

## 3. 비교 대상

| 이름 | 구현 |
|---|---|
| P0 | 질문 + 채점에 꼭 필요한 최소 답 형식 지시문 |
| P0-raw | 질문만 (참고용, 안내 PDF 정의 그대로) |
| P1 | LangChain `create_agent`, 도구 2개(BM25 검색·계산기), 최대 7스텝, 공통 답 형식 지시문 |
| M | EBA, LangGraph 단일 에이전트 |

결과표에는 P0와 P0-raw를 나란히 싣는다. 모든 파이프라인이 UNANSWERABLE로 기권할 수 있다 (M에만 허용하면 P1이 답할 수 없는 문항에서 0점이 되어 불공정).

## 4. 처리 흐름

```
질문
 └─▶ [라우터] 첫 호출 · 상한 512
       ├─ 수학 경로 ─▶ 그 자리에서 풀이 ──────────────▶ 답
       │                └─ 계산기 사용 시 ─▶ [마무리 호출] 상한 128 ─▶ 답
       └─ 검색 경로 ─▶ 검색(BM25, 모델 호출 없음)
                        ─▶ 압축(문장 창 BM25, 모델 호출 없음)
                        ─▶ [근거 판정 + 답] 상한 256
                              ├─ ANSWER   ─▶ 답
                              ├─ ABSTAIN  ─▶ UNANSWERABLE
                              └─ RETRIEVE ─▶ 후속 검색어로 재검색 (최대 2회)
                                             ─▶ 압축 ─▶ [근거 판정 + 답] …
                                             (마지막 판정은 RETRIEVE 불가)

모든 모델 호출에 적용: 출력 상한 · 루프 끊기 · 호출 예산 ≤ 4 / 문항
```

- 근거 없이 모델 지식만으로 답하는 **직답 경로는 두지 않는다.**
- 검색 경로의 모델 호출은 라우터와 "근거 판정 + 답"뿐이다.

## 5. 핵심 부품 (6개, 처음부터 포함)

| 부품 | 전략 | 하는 일 | 절제 변형 (끄면) | 담당 |
|---|---|---|---|---|
| 라우터 | ② | 첫 호출에서 검색 경로 / 수학 풀이 중 선택 | 모든 질문을 검색 경로로 | A |
| 다중 홉 재검색 | ③ | RETRIEVE면 빠진 정보로 후속 검색어를 만들어 재검색, 최대 2회 | RETRIEVE 제거, 한 번만 검색 | C |
| 근거 판정 | ③ | 답 생성과 같은 호출에서 ANSWER · RETRIEVE · ABSTAIN 판정 | ABSTAIN 제거 (재검색은 유지) | C |
| 검색 결과 압축 | ③ | 문단 제목을 붙인 앞뒤 1문장 창 단위로 BM25 점수 → 상위 m개. 재검색 때는 원래 질문 + 후속 검색어로 점수. 모델 호출 없음 | 상위 k개 문단을 통째로 | C |
| 출력 상한 | ① | 단계별 생성 토큰 하드 상한(num_predict). 잘리면 상한 2배로 한 번만 재시도 | 상한 제거 | D |
| 루프 끊기 | ① | 같은 도구를 같은 입력으로 다시 부르면 이전 결과와 함께 바로 답하게 함 | 반복 허용 | D |

## 6. 조건부 부품 (3개, 개발 세트 채택 기준 통과 시 포함)

| 부품 | 관련 핵심 부품 | 하는 일 | 목표 지표 | 담당 |
|---|---|---|---|---|
| 근거 장부 상세화 | 다중 홉 재검색, 근거 판정 | 질문을 필요한 정보 항목으로 나눠 FOUND · MISSING 기록, 빠진 것만 재검색 | HotpotQA 정답 수 증가, 또는 HotpotQA 문항당 호출 수 10% 감소 | C |
| 간결 출력 | 출력 상한 | 추론 단계를 짧게 쓰게 함. 수학은 추론 단계를 유지한 채 시작 | 문항당 평균 출력 토큰 10% 감소 | D |
| 동적 압축량 | 검색 결과 압축 | 질문 성격에 따라 남길 문장 수 조절 | 문항당 평균 입력 토큰 10% 감소 | C |

**채택 기준**: 개발 세트(유형당 20문항)에서 유형별 순정답 수가 줄지 않고 목표 지표가 좋아지면 채택. 개별 문항의 정답→오답 변화는 따로 기록. 채택된 부품은 그것만 뺀 절제 변형을 추가. 핵심 부품을 빼면 그 위에서 동작하는 조건부 부품도 함께 빠진다.

## 7. 실행 규칙

| 규칙 | 값 | 비고 |
|---|---|---|
| 호출 예산 | 문항당 최대 4회, 모든 문항 동일 | 가장 긴 경로 = 라우터 1 + 판정 1 + 재검색 후 판정 2. 잘림 재시도는 예산에서 제외, 비용 지표에는 포함. 예산 소진은 기권과 따로 집계 |
| 출력 상한: 첫 호출 (라우터 + 수학 풀이) | 512토큰 | GSM8K 추론 평균(200토큰대)의 약 2배, 폭주 방지용 |
| 출력 상한: 계산기 사용 후 마무리 | 128토큰 | 단답만 |
| 출력 상한: 근거 판정 + 답 | 256토큰 | 서술 + 판정 + 빠진 정보 + 답 |
| 잘림 처리 | 상한 2배로 한 번만 재시도 | 잘린 JSON은 파싱 불가 → "잘림"으로 따로 기록 |
| 근거 판정 출력 형식 | 자유 서술(1~2문장)을 맨 앞에 둔 JSON: 서술, 판정, 빠진 정보, 답 | Ollama 구조화 출력. 답 키가 서술보다 먼저 나오면 성능 하락(Let Me Speak Freely). 마지막 줄 태그 + 정규식 방식을 대조군으로 잘림률·파싱 실패율 비교 |
| 판정 값 | ANSWER / RETRIEVE / ABSTAIN | 기권 시 최종 출력 UNANSWERABLE |
| 재검색 | 최대 2회 | 마지막 판정은 RETRIEVE 불가 |
| k (검색 결과 수) | 개발 세트 검색 재현율로 결정 (1주차) | B 측정 |
| m (남길 문장 창 수) | 근거 문장 보존율 90% 이상인 가장 작은 값 (1차 검색·재검색 따로 측정) | C 측정 |
| 출력 상한 민감도 실험 | 근거 판정 단계만 96 / 160 / 256 | D. 가장 작은 값이 아니라 잘림 없이 정확도가 유지되는 범위를 찾는다 |
| P1 최대 스텝 | 7 | |
| 문항 타임아웃 | 120초 초과 시 오답 | |

**유형별 목표 호출 수** (결과 분석용 기준, 에이전트에 적용하는 상한 아님)

| 유형 | M의 경로 | 목표 호출 수 |
|---|---|---|
| GSM8K | 첫 호출에서 바로 풀이 (계산기 쓰면 마무리 1회) | 1~2 |
| SQuAD 2.0 (답 있음) | 라우터 → 검색 → 압축 → 근거 판정 + 답 | 2 |
| SQuAD 2.0 (답할 수 없음) | … → 단서 없으면 즉시 기권 | 2 |
| HotpotQA | … → 근거 판정 → 재검색 → 근거 판정 + 답 | 3~4 |

## 8. 평가 (요약 — 자세한 규칙은 [EVALUATION.md](EVALUATION.md))

- 평가 세트 120문항: HotpotQA 40(distractor dev, 다리형·비교형 반반) · SQuAD 2.0 40(dev, 답 있음 20 + 답할 수 없음 20) · GSM8K 40(test), 고정 시드
- 개발 세트: 유형당 20문항(SQuAD 2.0은 10 + 10), 평가 세트와 겹치지 않음
- 공용 코퍼스: HotpotQA 문항별 정답 문단 2 + 방해 문단 8, SQuAD 2.0 원래 문맥(함정 문단 포함)
- 11/12 세 가지를 함께 동결, 해시를 레포에 기록
- 채점: 텍스트는 SQuAD 정규화 후 EM(주) + F1(보조), 수치는 숫자 추출 후 수치 비교
- 측정: 본 비교 묶음 3라운드 + 절제 묶음 1라운드, 서로 다른 세션
- 통계: McNemar 정확 검정 (유형별 40문항 + 전체 120문항)

## 9. 범위 밖

| 항목 | 뺀 이유 |
|---|---|
| 근거 없는 직답 경로 | 평가 세트에 검색 없이 답하는 것이 정상인 유형이 없고, 7B는 환각이 늘어난다 |
| CONFLICT 상태 | 평가 세트에서 거의 발생하지 않음. 로그에서 사례만 수집 |
| 학습된 라우터·압축 모델 | "파이프라인별 모델 상이"로 읽힐 여지, VRAM 추가 |
| 웹 검색 보충 (CRAG 원안) | 외부 API 금지 → 기권으로 대체 |
| 멀티 에이전트 | 호출이 늘어 파레토 개선 목표와 어긋남 |
| 메모리 요약, 도구 호출 형식 검증 | 재검색이 최대 2회라 필요성 낮음. P1 로그에서 문제가 크면 11/19 조건부 후보 |
| 한국어 벤치마크, 비텍스트 입력 | 유형당 문항 수 감소, 고정 모델은 텍스트 전용 |
