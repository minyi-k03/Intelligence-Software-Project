## 질문

근거 판정 + 답 호출의 출력 형식을 Ollama 구조화 출력 JSON(기본, ADR-0004)으로 둘 것인가, 자유 서술 뒤 마지막 줄 태그(`DECISION:` / `MISSING:` / `ANSWER:`, 대조군)로 바꿀 것인가 (SPEC §7, INTERFACES §5).

## 목표 지표와 채택 기준

- 목표 지표: 잘림률, 파싱 실패율 (SPEC §7), 그리고 정확도
- 채택 기준: 태그가 잘림률·파싱 실패율을 줄이면서 유형별 정답 수가 줄지 않으면 태그로 바꾼다. 아니면 JSON(기본)을 유지한다

## 결정

**JSON(기본)을 유지한다.** 채택 기준의 목표 지표(잘림률·파싱 실패율)가 두 형식 모두 0%라 태그로 바꿀 근거가 없다. 정확도도 30%로 같고 문항별 차이는 4 대 4로 대칭이다(p = 1.00). 태그는 출력 토큰이 23% 적지만 판정 호출이 11% 많고, 과잉 기권이 적은 대신 답할 수 없음 문항 정답이 6 → 4로 줄었다. 20~40문항 규모에서 어느 쪽도 우세하지 않다.

`judge()`의 기본값 `output_format="json"`을 그대로 두며, 설정·코드 변경은 없다.

## 함께 발견한 것 (형식과 무관, 후속 작업 필요)

**1. 근거 판정의 과잉 기권이 크다 (두 형식 공통).** 답이 있는 30문항 중 JSON 20, 태그 14문항이 기권했다. 그중 **근거에 정답 문자열이 들어 있었는데 기권한 문항이 JSON 11, 태그 7**이다. 근거 부족이 아니라 판정이 원인이다.

| 답이 있는 30문항 | JSON | 태그 |
|---|---|---|
| 정답 | 6 | 8 |
| 오답 (근거에 정답 있음 / 없음) | 3 / 1 | 6 / 2 |
| 기권 (근거에 정답 있음 / 없음) | 11 / 9 | 7 / 7 |

- 1차 근거에 이미 정답이 있던 19문항 중, 첫 판정이 RETRIEVE였던 문항이 JSON 10, 태그 9다. 답이 있는데 더 찾으러 간다.
- **빠진 정보(후속 검색어)에 정답 자체를 쓴 문항**이 JSON 4, 태그 3이고 모두 최종 기권했다. 예: `hotpotqa-0040`(정답 Aristotle)의 후속 검색어가 `Aristotle`, `hotpotqa-0046`(정답 Montana State University)의 후속 검색어가 `Montana State University` 두 번이다.
- 이슈 #16(공통 지시문의 기권 문장이 아는 답까지 기권하게 만든다)과 같은 방향의 결과다. 근거 판정 프롬프트에는 ABSTAIN 선택지 설명과 공통 지시문의 기권 문장이 함께 있다.

**2. 근거 부족도 있다.** 기권 중 근거에 정답이 없던 문항이 JSON 9, 태그 7이다. 이번 실행은 `compress.m`이 임시값 3이었다(실험 C-2: k=3이면 m=6 권장). `m`이 확정되면 줄어들 수 있다.

**3. 출력 상한에 여유가 크다.** 호출당 최대 출력 토큰이 89~93으로 `cap.judge` 256의 36% 수준이다. 출력 상한 민감도 실험(D-4, 96 / 160 / 256)에 참고 자료로 넘긴다.

## 이 결과를 읽을 때 주의할 점

- 문항이 40개라 형식 간 차이(4 대 4)는 우연 범위 안이다. "두 형식이 같다"가 아니라 "차이를 보일 근거가 없다"로 읽는다.
- `compress.m=3`(임시값)과 그래프 없이 이은 검색 경로에서의 결과다. 통합(A-5b) 뒤 M의 dev 로그로 다시 확인한다.
- "근거에 정답이 있음"은 압축이 남긴 문장 창(앞뒤 1문장 포함)을 정규화한 텍스트에 정답 문자열이 들어 있는지로 셌다. 정답이 근거에 있어도 그 문장만으로 답할 수 있다는 보장은 아니다(특히 HotpotQA 다리형).
