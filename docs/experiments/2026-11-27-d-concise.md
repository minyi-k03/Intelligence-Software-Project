# D-5 조건부 간결 출력 — 코드 완료, 개발 비교 측정 대기

2026-11-27 기준. **간결 출력 코드는 구현했으나 실제 모델 비교 결과는 없다.** 평균 출력 토큰 10% 감소와 유형별 순정답 수 비감소는 아직 판정할 수 없다.

## 목적과 기존 방식의 문제

[SPEC §6](../SPEC.md)의 목표는 정답에 필요한 근거와 수학 풀이 단계를 남기면서 반복 설명·질문 재진술·이미 확인한 근거의 재검토·무관한 설명을 줄이는 것이다. 기존 M 개발 로그에는 최종 답과 호출별 토큰은 있지만 모델 원문이 없다. 따라서 어느 설명이 실제로 불필요한지 로그에서 단정하지 않았고, P1의 토큰 수를 M 기준선으로 대체하지 않았다.

## 구현과 변경 파일

[간결 출력 훅](../../src/meba/conditional/concise.py)은 A-5a 그래프의 `ConditionalHooks.concise(step, model_input)` 규격에 붙는다. `router`의 **수학 경로**에는 필수 계산식·중간값·논리적 순서를 유지하고 반복 설명만 줄이라고 영어로 지시한다. `judge`에는 결정적인 근거 또는 빠진 사실만 짧게 쓰도록 지시한다. 이미 짧은 최종 답만 쓰는 `finalize`는 변경하지 않는다. 검색 경로의 기존 한 줄 응답 지시, 공통 `Final answer:` 형식, 판정 JSON 필드·순서는 그대로 둔다. `type`·`source` 등 문항 유형은 입력하지 않는다.

훅은 원본 메시지를 수정하지 않고 같은 `list[dict]` 또는 `list[tuple[str, str]]` 형식의 새 메시지를 돌려준다. 출력 상한은 낮추지 않는다. [실행 등록](../../scripts/run_eval.py)의 `m_concise`는 `MComponents(concise=True)`만 켠다. 기본 `m`은 그대로다. [단위 테스트](../../tests/test_concise.py) 5개가 메시지 형식, 수학 필수 단계 지시, 공통 형식 보존과 스위치 연결을 확인했다.

## 동일 조건 비교 절차

[실험 계획](../../configs/d5_concise.json)의 공통 설정을 읽어 [비교 실행기](../../scripts/run_concise_experiment.py)가 기본 `m`과 `m_concise`를 같은 개발 세트 60문항, 같은 라운드 `r23`, 같은 모델·도구·채점기·시드·출력 상한으로 실행한다. 실험 조건 차이는 간결 출력 훅뿐이다. 문항별 정식 로그와 모델 원문·종료 사유 보조 로그를 즉시 JSONL에 저장하고, 중단 시 이어서 돈다. 평가 세트는 튜닝에 쓰지 않는다.

```sh
python -m scripts.run_concise_experiment --verify 2
python -m scripts.run_concise_experiment
python -m scripts.run_concise_experiment --summarize
```

정식 파일은 `results/runs/dev/r23/m.jsonl`, `m_concise.jsonl`이며, 모델 원문은 같은 폴더의 `m_reason_trace.jsonl`, `m_concise_reason_trace.jsonl`에 남는다. 수학 경로의 원문을 문항별로 대조해 계산식·중간값이 유지됐는지 **사람이 검토**해야 한다. 원문이 없으면 유지 여부는 미확인으로 둔다.

동일 문항 대응, 토큰 감소율, 유형별 순정답 수, 자유 텍스트 최종 답 줄과 판정 JSON 형식의 별도 검사 규칙은 [비교 집계 테스트](../../tests/test_concise_experiment.py) 2개로 확인했다. 성공은 **평균 출력 토큰 10% 이상 감소**, **모든 유형의 순정답 수 0 이상**, **수학 필수 계산 과정 유지**, **형식·채점 호환**을 모두 만족할 때만 판정한다. 정답 수가 같아도 어떤 문항이 악화됐는지 따로 기록한다.

## 실행 결과와 한계

현재 호스트에서 `python3 -m scripts.run_concise_experiment --verify 2`를 시도했으나 처음에는 `langchain_core` 부재로 모델 호출 전 중단됐다. 의존성 사전 확인을 추가한 뒤에는 `langchain-ollama` 부재를 로그 생성 전에 명시적으로 알린다. Python 3.9.6은 프로젝트 요구 버전(3.10+)보다 낮고 Ollama도 없다. 과거 M 개발 로그(`results/runs/dev/r6/m.jsonl`)의 31/60 정답·워밍업 제외 출력 8,151토큰은 **참고치**일 뿐, 같은 라운드의 간결 조건과 대응하지 않으므로 이 표의 Baseline으로 쓰지 않는다. 출력 감소율·유형별 순정답 수·수학 추론 유지·목표 달성 여부는 **미판정**이다.
