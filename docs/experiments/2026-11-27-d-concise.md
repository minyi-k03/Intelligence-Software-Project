# D-5 조건부 간결 출력 — 선행 작업 대기

2026-11-27 기준. 설계와 실행 가능성을 점검했으며, 코드·비교 실험은 아직 수행하지 않았다. 아래 표의 빈 결과는 예상값이 아니다.

## 목적과 기존 방식

[SPEC §6](../SPEC.md)의 조건부 부품 `concise`는 수학 풀이에 필요한 계산과 논리 단계를 유지하면서 문항당 평균 출력 토큰을 10% 이상 줄이고, 유형별 순정답 수를 감소시키지 않아야 한다. P1 개발 로그의 기록 출력은 워밍업 제외 3,916토큰/59문항이나, M의 출력 원문과 단계별 사용량은 없다. 따라서 M에서 반복 설명, 질문 재진술, 이미 확인한 근거 재검토가 실제로 얼마나 발생하는지는 **측정 불가**다. [D-3 분석](2026-11-23-d-p1-log-audit.md)의 P1 수치를 M 기준선으로 사용하지 않는다.

## 코드 연결 조건과 설계

[구현 계획](../IMPLEMENTATION_PLAN.md)은 A-5a의 그래프 골격과 조건부 on/off 연결을 **코드 선행 조건**, A-5b의 개발 세트 완주를 **실험 선행 조건**으로 둔다. 현재 체크아웃(`Dongsub` @ `f94acf3`)에 `src/meba/graph.py`, `tests/test_graph.py`가 없어 두 조건 모두 충족되지 않았다. `src/meba/conditional/concise.py`를 지금 작성해도 그래프에서 어느 메시지에 적용하고 어떻게 끄는지 검증할 경계가 없다. 팀원이 맡은 그래프를 임의로 대신 구현하지 않았고, `concise.py`와 테스트 파일도 생성하지 않았다.

연결 구조가 들어오면 영어 프롬프트에서 중복 설명·질문 재진술·이미 확인한 근거의 반복 검토·정답과 무관한 설명을 줄이도록 지시한다. 답 도출에 필요한 핵심 근거는 남기고, 수학 경로는 계산식·중간값·논리적 순서를 남긴다. `cap`을 낮춰 출력을 자르는 방식은 사용하지 않는다. 문항 유형(`type`, `source`)은 프롬프트나 라우터에 전달하지 않고, 그래프가 이미 결정한 일반적인 `math`/`search` 경로만 사용한다. 공통 답 형식 지시문과 근거 판정 JSON 키 순서·스키마는 유지한다. on/off는 A-5a의 기존 조건부 스위치에 연결한다. 실제 메시지 변경 범위는 A-5a 코드와 C 담당의 판정 프롬프트를 확인한 뒤 확정한다.

## 비교 실험과 판정 방법

Baseline과 Concise는 동일한 개발 세트 60문항, 모델, 시드, 채점기, 검색 설정, 출력 상한을 사용하고 간결 출력 on/off만 바꾼다. 문항별 JSONL을 즉시 저장하고 설정 스냅샷을 남겨 재시작 가능하게 한다. 수학 추론 유지 여부는 GSM8K 원문에서 필요한 계산식과 중간 단계가 남았는지 점검한다. 로그에 최종 답만 남으면 판단 불가로 표시한다. 평가 세트는 프롬프트 조정에 쓰지 않는다.

| 지표 | Baseline | Concise | 판정 방법 |
|---|---|---|---|
| 전체 정확도·정답 수 | 미측정 | 미측정 | `correct=true` 수 / 60(워밍업·타임아웃 포함) |
| HotpotQA 정답 수·정확도 | 미측정 | 미측정 | 정답 수 / 20 |
| SQuAD 2.0 정답 수·정확도 | 미측정 | 미측정 | 정답 수 / 20 |
| GSM8K 정답 수·정확도 | 미측정 | 미측정 | 정답 수 / 20 |
| 평균·전체 출력 토큰 | 미측정 | 미측정 | 워밍업 제외 기록 토큰 합 / 비용 대상 문항 수, 타임아웃 병기 |
| 평균 출력 토큰 감소율 | — | 미측정 | `(Baseline 평균 - Concise 평균) / Baseline 평균 × 100` |
| 유형별 순정답 수 | — | 미측정 | 같은 `qid`의 오답→정답 수 - 정답→오답 수; 각 유형에서 0 이상 |
| 형식 오류율 | 미측정 | 미측정 | 해당 출력 형식을 검증할 수 있는 원문/파싱 기록을 분모로 사용 |
| 실제 출력 잘림 비율 | 미측정 | 미측정 | 종료 사유와 원문으로 확인된 호출 / 종료 사유를 확인한 호출 |
| 수학 추론 단계 유지 | 미측정 | 미측정 | GSM8K 원문에서 필수 계산 과정 확인 |

성공 판정은 **출력 토큰 10% 이상 감소, 세 유형의 순정답 수 모두 0 이상, 수학 필수 추론 유지, 기존 출력 형식 및 평가 시스템 호환**을 모두 요구한다([SPEC §6](../SPEC.md)). 유형별 순정답 수는 정답 수 차이와 수치상 같지만, 문항별 악화 사례를 따로 기록한다. 정확도만 같아도 같은 문항이 유지됐다고 추정하지 않는다.

## 실행 명령, 테스트, 결론

실행 명령은 **없다**. 현재 [실행 스크립트](../../scripts/run_eval.py)의 M 등록은 존재하지 않는 `src.meba.graph:build_m`을 가리키고, Ollama·LangChain·pytest도 이 환경에 없다. A-5a/A-5b가 들어오면 실제 연결 방식에 맞춰 `concise.py`와 on/off 테스트를 작성한 후 동일 조건의 독립 개발 라운드로 실행한다. 출력 토큰 감소율, 유형별 순정답 수, 수학 추론 유지, 목표 달성 여부는 모두 **미판정**이다.
